# ail-edit: the polished, AI-first editor (plan, 2026-11-09)

Written by the Fable design lane for Kaleb's ask: make the editor look nicer,
make it feature-full, and add the AI-first features that AIL is specifically
equipped for. Implementation is by Sonnet lanes, one per slice below. The app
lands on its own against the ail commit pinned in `.ail-version`; a slice that
needs a language or std change asks the coordinator for an ADR in kksimp/ail
(only Fable allocates ADR numbers).

## 1. What exists

`edit.ail` (5,426 lines, one file) is a headless `Editor` value, `Command`s and
a pure `render` to a `Screen` of colored cells (ADRs 0180, 0181), with a
`Workspace` of tabs, a file tree, a picker, panes, a command palette and a
`std.ui` window: a character grid with one monospace font, no images, no
pixel layout, no proportional text, no hover. 55 headless tests run with
`ail test edit.ail`; `--print --at= --key= --type=` drives any state from the
command line, which is how every feature is tested without a display.

It already reaches much of the semantic API: `ail check --json` with fixes,
`ail explain`, `ail api --symbols|--locals|--type|--refs|--card|--text`,
`ail fmt`, `ail run`, `ail test`, `--trace=all`, `--coverage=lines`,
`ail check --errors`. What it does not reach is everything built since
October: `ail task`, `ail ask`, impact, `ail diff`, `ail api --diff`,
`ail verify --diff`, `ail edit`, record/replay and `ail replay --shrink`,
probes (`ail run --at --show`), `--watch`, `--values`, `--contracts`,
`--update`, `ail sanitize`, `ail leak`, `ail fix`, `ail mcp`, `ail lsp`.

## 2. Decisions

**D1. Rendering moves to `std.app` canvas, the core stays headless.** The
`std.app` host (macOS SwiftUI, Linux GTK, Windows) draws `Op`s: proportional
and monospace text in any size with bold/italic/underline, fills, strokes,
shades, clips, pictures and bitmaps, native popup menus (std.app.18), native
open dialogs (std.app.22), clipboard (std.app.26), paste events, click
counts, measured text (std.app.13). Garlic's Chromium-style chrome is built
on it. `std.ui` cannot grow icons, a minimap, inlay hints in a smaller font
or a smooth scrollbar without becoming `std.app`. The `Editor`, `Command`,
`Screen` and every `--print` test stay as they are; the window layer turns a
`Screen` plus a new `Paint` list (pixel chrome, overlays) into ops. Rejected:
polishing the cell grid (no path to the features above); `std.gfx` (a game
frame loop, no native text input, menus or dialogs).

**D2. One feature, one module.** Every slice after S1 adds a directory
`features/NAME/NAME.ail` (modules are directories) and touches `edit.ail`
in at most three places: one `use`, one `key_rows()` entry per key, one
dispatch line. Ten lanes edit one 5,400-line file otherwise. The same rule
ADR 0823 gives the compiler's lowering files.

**D3. Shell out, as the LSP does.** Each feature runs the `ail` command that
owns it (ADR 0918's shape) and parses its `--json`. No second analysis in
the editor; the checker stays the only checker. Long runs (`--shrink`,
`--contracts`, `sanitize`) run in a task with a cancel and a progress row.

**D4. Agent-first means agent-visible.** Every panel's content is also a
`--print` view and a `--json` dump (`--print --json`), so an agent driving
the editor from the command line sees what a human sees. The editor and an
agent working in the same directory share `.ail-task` (ADR 0917).

## 3. The feature set

### GUI
- Pixel layout: sans chrome, mono code; tab strip with close buttons and
  dirty dots, drag to reorder; activity bar with icons; status bar segments
  (position, check counts, tests, token count, task state); panel row at the
  bottom (Problems, Output, Tests, Trace, Search, Task) and a side panel
  (Explorer, Outline, Card, Ask); draggable splitters; smooth per-pixel
  scrolling; a scrollbar with error, warning, search and change marks; a
  minimap; indent guides; bracket-pair colors; sticky function headers;
  current-line highlight; native context menu and menu bar; light and dark
  follow the system; font family and size in settings.
- Editing: multi-cursor (Ctrl-D next occurrence, Alt-click), folding by
  indentation (AIL blocks are indentation), split view (two tabs side by
  side), breadcrumbs (`ail api --text` outline), drag and drop tabs, zen mode,
  rich hover cards, signature help as a popup, a welcome screen with recent
  projects.

### AI-first (what only an AIL editor can do)
- **Semantic layer:** highlighting by declaration kind from `--symbols`;
  inlay hints for local types (`--locals`), effects and error sets
  (`--card`), contracts shown over a function; code lens: `N refs`, `run
  test`, `effects: fs net`.
- **Fix rules:** fix-all (first non-overlapping fix of each diagnostic, as
  `ail lsp` does), a preview diff for every fix, `ail fix` whole-file with
  preview, `ail explain` rendered with the rule id linked to the spec.
- **Task protocol:** a Task panel over `ail task start|status|verify|finish|
  abort`: goal, base, changed declarations, affected tests, changed effects,
  verified green or red, the `next` step. The same state an agent sees.
- **Impact analysis:** after each save (and 500 ms after typing stops, as
  problems do) `ail ask PROGRAM --affected` marks affected functions and
  tests in the gutter and scrollbar; `ail test --affected` runs them.
- **Semantic diff:** `ail diff --rev HEAD`, `ail api --diff` with `breaking:`
  marks, `ail verify --diff` as a four-part report (proved, tested,
  unverified, failures) in a panel, plus a git change gutter.
- **Tests, replay and shrink:** a test tree with pass/fail and coverage; run
  one test; `--update` accepts stale expectations with a preview; a failed
  test offers Record, Replay, Trace over replay and Shrink (`ail replay
  --shrink` with its time budget and progress); `ail test --contracts` shows
  the smallest failing input inline at the contract.
- **Probes and diagnosis:** click a line, name variables: `ail run --at
  FILE:LINE --show a,b` shows each hit as a row, values inline; `--watch
  NAME`; trap frame values (`--values`) at the trap line; the trace pane as
  a collapsible tree with filters; `ail sanitize` schedules and `ail leak`
  growth by root as panels; `ail check --errors` error flow already exists.
- **Ask bar:** `ail ask` questions as a prompt (who calls X, who writes or
  reads field F, what does X call, which effects reach X, who uses type T)
  with jump lists; a call-hierarchy tree; the program card's effects graph.
- **Token meter:** AIL's first design criterion is tokens; the status bar
  shows the file's and the selection's token count (`ail api --tokens`), and
  the Explorer shows per-file counts and the project total.
- **Agent co-editing:** the editor watches the directory: files changed by an
  agent reload (unless dirty), and lines changed since the last human save
  show an agent mark; "Copy for agent" packs the selection, its card entries
  and its diagnostics under a token budget (uses `ail context` when ADR 0891
  lands, local assembly until then); "Apply agent edit" reads `ail edit`
  hunks from the clipboard or a file and previews them before `ail edit`
  applies, formats and checks.
- **Workspace:** git status in the tree, module (`ail.pkg`, `use`) aware
  navigation, `ail new` scaffolds, workspace-wide go-to-symbol, settings
  file with a UI, key rebinding, the key table regenerated into README.

### Deferred, with the reason
- `ail infer` contract ghost text, `ail test --mutate` score, `ail check
  --perf` hints: their ADRs (0895-0897) are Proposed, not built. Each is one
  panel when it lands.
- Hosting `ail lsp` inside the editor: the server shells out per request as
  the editor does, so nothing is saved.
- The editor as an MCP server for agents: open question for Kaleb after D4's
  `--print --json` exists; `ail mcp` may be the right place instead.

## 4. Slices (one Sonnet lane each)

Rules for every slice: branch `claude/edit-SN-name` off `main` of
kksimp/ail-edit; keep `.ail-version` as pinned (ask the coordinator before
moving the pin); every feature headless-testable with `--print` and covered
by `@test`s; `tools/check.sh` green on a Kaleb machine through the runner
before READY; update README's key table and the `--keys` test; D2's
three-touch rule for `edit.ail`; ASCII only in rendered text until S1 lands
(the std.ui font lacks other glyphs). S1 lands first; S2-S10 start now on
the cell `Screen` and need no change when S1 lands, because `Screen` stays.
